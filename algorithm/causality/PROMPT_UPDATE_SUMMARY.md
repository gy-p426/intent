# 因果分析提示词更新总结

## 更新时间
2025/01/21

## 更新目标
修改因果分析的提示词，让LLM能够自动寻找自变量，同时添加清晰的格式示例，确保返回数据格式的准确性。

## 核心改进

### 1. 自变量自动发现
- **因变量位置固定**：因变量始终作为第一列（用户指定的目标变量）
- **自变量自动寻找**：LLM主动从数据库schema中寻找所有可能影响因变量的数值型字段
- **无数量限制**：移除了自变量数量限制，允许LLM包含所有潜在的影响因素
- **全面覆盖**：提示LLM考虑营销、产品、时间、地理等多个维度的业务指标

### 2. 格式示例增强
参考关联分析的格式示例，添加了详细的格式说明：

#### 列的顺序
```json
["销售额", "广告投入", "促销活动", ...]
```
- 因变量（销售额）必须放在第一位
- 然后是所有自变量

#### required_columns
```json
["销售额", "广告投入", "促销活动", "季节", "价格", "库存", "客户数量", "访问量"]
```
- 必须包含所有列（因变量+自变量）
- 顺序与parameter_mapping一致
- 必须与normalized_query中使用的列名完全一致

#### normalized_query格式
```
"获取[时间范围/条件]的[列1]、[列2]、[列3]...，返回[列1]、[列2]、[列3]...共N列数据"
```

**示例1**：
```
"获取2023年1月到2023年12月期间的销售数据的销售额、广告投入、价格，返回销售额、广告投入、价格共3列数据"
```

**示例2**：
```
"获取历史销售数据的销售额、广告投入、促销活动、季节、价格、库存、客户数量、访问量，返回销售额、广告投入、促销活动、季节、价格、库存、客户数量、访问量共8列数据"
```

#### 列名一致性
- parameter_mapping、required_columns、normalized_query中的列名必须完全一致
- 都使用列注释（中文名称），不使用列的英文名称
- 三个字段中的列名顺序必须一致
- 因变量始终在第一位

#### 列数计算
```
总列数 = 1个因变量 + N个自变量
```
示例：1个因变量 + 7个自变量 = 共8列数据

## 提示词关键指令

### System Prompt 关键点
1. 因变量必须指定一个（结果变量）
2. 自变量自动从数据库中寻找所有可能影响因变量的数值型字段，数量不限
3. 主动分析数据库schema，找出所有可能与因变量相关的数值型字段
4. 不要遗漏任何可能有用的字段
5. 可以包含时间、地理、分类等维度字段（如果是数值型）
6. 字段数量没有限制，尽可能全面地包含所有潜在的影响因素

### User Prompt 关键点
1. 从数据库schema中识别因变量（用户想要分析的目标变量）
2. 主动从数据库schema中寻找所有可能影响因变量的数值型字段作为自变量
3. 不要只选择用户明确提到的字段
4. 要全面分析数据库中所有可能相关的数值型字段
5. 考虑业务逻辑，包含所有潜在的影响因素
6. 字段数量不限，尽可能全面
7. **normalized_query格式要求（重要）**：
   - 必须写明返回的所有列名（因变量+所有自变量）
   - 必须标明返回的总列数
   - 格式："获取[条件]的[列1]、[列2]、[列3]...，返回[列1]、[列2]、[列3]...共N列数据"

## 验证要点

### 参数验证
- 移除了自变量数量上限（原来限制为10个）
- 保留了最少1个自变量的要求
- 记录日志显示实际包含的自变量数量

### 输出格式验证
LLM输出的JSON应该包含：
1. `parameter_mapping.dependent_variable`: 单个因变量（字符串）
2. `parameter_mapping.independent_variables`: 自变量列表（数组）
3. `required_columns`: 所有列的列表（因变量+自变量）
4. `normalized_query`: 明确说明返回的列和列数的查询描述

## 与关联分析的对比

### 相似点
- 都使用详细的格式示例
- 都强调列名一致性
- 都要求明确说明返回的列数

### 不同点
- **因果分析**：因变量固定在第一列，自变量由LLM自动发现
- **关联分析**：根据分析模式（bivariate/pairwise/multivariate）确定列的角色和顺序

## 文件修改
- `intent/algorithm/causality/extractor.py`
  - 更新了system_prompt，添加详细的格式示例说明
  - 更新了user_prompt，强调normalized_query格式要求
  - 移除了validate_parameters中的自变量数量上限

## 预期效果
1. LLM能够自动从数据库schema中发现所有相关的自变量
2. 输出的normalized_query格式更加规范和明确
3. 减少因格式不明确导致的SQL生成错误
4. 提高因果分析的全面性和准确性
