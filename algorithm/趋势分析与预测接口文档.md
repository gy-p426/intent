## 1. 返回数据总览

### 1.1 我会收到什么？

当用户提问后，系统会返回一个 JSON 对象，包含以下主要内容：

```
┌─────────────────────────────────────────────────────────────┐
│                      返回数据结构                            │
├─────────────────────────────────────────────────────────────┤
│  step          → 当前执行到哪一步了                          │
│  status        → 这一步是否成功                              │
│  data          → 具体的数据内容（重点关注这里）               │
│  timestamp     → 返回时间                                    │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 完整返回示例

```json
{
  "step": "completed",
  "status": "completed",
  "data": {
    "algorithm_type": "trend",
    "algorithm_type_chinese": "趋势分析",
    "algorithm_result": { /* 算法原始结果（字段名为中文） */ },
    "sql_statement": "SELECT timestamp, value FROM sales_data ORDER BY timestamp",
    "normalized_query": "分析销售数据的趋势变化",
    "execution_summary": "趋势分析完成，检测到上升趋势",
    "data_summary": {
      "input_rows": 100,
      "sql_execution_time": 125
    },
    "readable_result": {
      "llm_analysis": "根据分析结果，您的销售数据呈现明显的上升趋势...",
      "technical_details": { /* 技术细节 */ },
      "analysis_source": "llm_enhanced"
    },
    "message": "趋势分析算法执行完成"
  },
  "timestamp": "2024-12-29T10:30:00.000Z"
}
```

### 1.3 字段说明（通俗版）

| 字段名 | 是什么意思 | 举例 |
|--------|-----------|------|
| `step` | 当前执行到哪一步 | `"completed"` 表示全部完成 |
| `status` | 这一步成功了吗 | `"completed"` 成功，`"error"` 失败 |
| `data.algorithm_type` | 用的是什么算法 | `"trend"` 趋势分析，`"predict"` 预测 |
| `data.algorithm_type_chinese` | 算法的中文名 | "趋势分析"、"预测分析" |
| `data.algorithm_result` | 算法计算出的原始数据 | 用于画图表（字段名为中文） |
| `data.readable_result` | **🌟 最重要！给用户看的分析结果** | 自然语言描述 |
| `data.message` | 简短的状态消息 | "趋势分析算法执行完成" |
| `data.sql_statement` | 执行的SQL语句 | 用于调试 |
| `data.data_summary` | 数据摘要信息 | 输入行数、执行时间等 |

## 2. 智能分析结果（readable_result）

### 2.1 这是什么？

`readable_result` 是系统用 AI 自动生成的**用户友好的分析报告**。

**简单说**：这就是你要展示给用户看的主要内容！

### 2.2 结构说明

```json
{
  "readable_result": {
    "llm_analysis": "这里是给用户看的分析文字...",
    "technical_details": {
      "summary": "算法执行完成",
      "status": "success",
      "timestamp": "2024-12-29T10:30:00.000Z",
      "metrics": { /* 关键指标 */ },
      "raw_data": { /* 原始数据摘要 */ }
    },
    "analysis_source": "llm_enhanced"
  }
}
```

### 2.3 字段详解

| 字段 | 是什么 | 前端怎么用 |
|------|--------|-----------|
| `llm_analysis` | **给用户看的分析文字** | 直接显示在页面上，这是最重要的内容 |
| `technical_details` | 技术细节（给想深入了解的用户看） | 可以做成"展开查看详情"的折叠区域 |
| `analysis_source` | 分析是怎么生成的 | 用来显示一个小标签 |

### 2.4 analysis_source 的含义

| 值 | 意思 | 建议显示 |
|----|------|---------|
| `llm_enhanced` | AI 智能分析生成的 | 显示 "🤖 AI智能分析" 标签 |
| `fallback` | 系统自动生成的基础分析 | 显示 "📊 基础分析" 标签 |

## 3. 趋势分析算法

### 3.1 这个算法是干什么的？

趋势分析用来回答这类问题：
- "销售额是在涨还是在跌？"
- "数据有没有周期性规律？"
- "这个趋势明显吗？"

趋势分析有两种模式：
- **趋势分解**（decomposition）：把数据拆成趋势、季节性、随机波动三部分
- **趋势检测**（detection）：判断数据是涨是跌，给出统计结论

### 3.2 趋势检测结果（通俗版）

**这是最常用的模式**，判断数据是涨是跌。

```json
{
  "检测结果": {
    "趋势方向": "increasing",
    "Sen斜率": 0.0234,
    "p值": 0.0012,
    "统计显著性": true,
    "结果解释": "检测到明显的上升趋势"
  }
}
```

| 字段 | 通俗解释 | 怎么用 |
|------|---------|--------|
| `趋势方向` | **趋势方向** | `"increasing"` = 上涨 📈<br>`"decreasing"` = 下跌 📉<br>`"no trend"` = 没有明显趋势 ➡️ |
| `Sen斜率` | **变化速度**（斜率） | 数字越大变化越快。比如 0.02 表示平均每个时间单位增加 0.02 |
| `p值` | **结果可信度** | 越小越可信。< 0.05 表示结果很可靠 |
| `统计显著性` | **结果是否可靠** | `true` = 可以相信这个结论<br>`false` = 结论不太确定 |
| `结果解释` | **结论的中文描述** | 直接显示给用户看 |

**前端展示建议**：
```
┌─────────────────────────────────────────┐
│ 📈 趋势分析结果                          │
├─────────────────────────────────────────┤
│                                         │
│  趋势方向：上涨 📈                       │
│  变化速度：每天增加约 2.3%               │
│  结论可靠性：高 ✓                        │
│                                         │
│  [查看趋势图表]                          │
│                                         │
└─────────────────────────────────────────┘
```

### 3.3 趋势分解结果（通俗版）

把数据拆成几个部分来分析。

```json
{
  "分解结果": {
    "趋势分量": [...],
    "季节性分量": [...],
    "残差分量": [...]
  }
}
```

| 字段 | 通俗解释 | 用途 |
|------|---------|------|
| `趋势分量` | **长期趋势线** | 去掉波动后的整体走向，用来画趋势线图 |
| `季节性分量` | **周期性波动** | 比如"每周一销量低，周末销量高"这种规律 |
| `残差分量` | **随机波动** | 去掉趋势和周期后剩下的随机变化，一般不用展示 |

### 3.6 通俗摘要字段说明

`通俗摘要` 是专门为非专业用户设计的通俗易懂的分析结果摘要。

#### 字段说明

| 字段 | 类型 | 说明 | 前端展示建议 |
|------|------|------|-------------|
| `标题` | string | 带emoji的分析标题 | 作为卡片标题显示 |
| `关键发现` | array[string] | 关键发现列表 | 用列表形式展示，每条一行 |
| `详细解释` | string | 详细解释（支持Markdown） | 作为主要内容展示 |
| `建议` | array[string] | 建议列表 | 用高亮卡片展示 |

```
┌─────────────────────────────────────────────────────────────┐
│ 📊 趋势分解分析结果                                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
```

## 4. 单变量预测算法

### 4.1 这个算法是干什么的？

单变量预测用来回答这类问题：
- "预测一下明天的销售额"
- "下周的访问量大概是多少？"
- "未来30天的趋势会怎样？"

**特点**：只根据一个指标的历史数据来预测未来。

### 4.2 返回数据说明（通俗版）

```json
{
  "是否成功": true,
  "预测结果": {
    "预测值": [110.5, 112.3, 115.0],
    "时间点": ["2024-01-15", "2024-01-16", "2024-01-17"],
    "置信下限": [105.2, 107.1, 109.5],
    "置信上限": [115.8, 117.5, 120.5]
  },
  "使用模型": "prophet",
  "数据分析": {
    "是否有季节性": true,
    "趋势方向": "increasing"
  }
}
```

| 字段 | 通俗解释 | 怎么用 |
|------|---------|--------|
| `是否成功` | **预测是否成功** | `true` 成功，`false` 失败 |
| `预测值` | **预测值列表** | 这就是预测出来的数字！按时间顺序排列 |
| `时间点` | **对应的时间点** | 每个预测值对应哪一天/哪个时间 |
| `置信下限` | **预测下限** | 实际值大概率不会低于这个数 |
| `置信上限` | **预测上限** | 实际值大概率不会高于这个数 |
| `使用模型` | **用的什么模型** | `"prophet"` 或 `"arima"`，可以显示给用户 |
| `是否有季节性` | **数据有没有周期规律** | `true` = 有规律（如每周重复） |
| `趋势方向` | **整体趋势** | `"increasing"` 上涨，`"decreasing"` 下跌 |

### 4.3 置信区间是什么意思？

简单说：**预测值是一个范围，不是精确数字**

## 5. 多变量预测算法

### 5.1 这个算法是干什么的？

多变量预测考虑多个因素来预测，比如：
- "根据天气、节假日、促销活动，预测销售额"
- "综合多个指标预测未来趋势"

**特点**：综合多个相关因素，预测更准确。

### 5.2 返回数据说明（通俗版）


| 字段 | 通俗解释 | 怎么用 |
|------|---------|--------|
| `预测值` | **预测值列表** | 预测出来的数字 |
| `时间点` | **对应时间点** | 每个预测值对应的时间 |

### 5.3 metrics（模型评估指标）是什么意思？

评估指标告诉你模型预测得准不准：

| 指标 | 通俗解释 | 怎么看 |
|------|---------|--------|
| `均方根误差` (RMSE) | **平均误差大小** | 越小越好，比如 5.23 表示平均误差约 5.23 |
| `平均绝对误差` (MAE) | **平均偏差** | 越小越好，比如 3.45 表示平均偏差约 3.45 |
| `决定系数` (R²) | **模型解释力** | 0-1之间，越接近1越好。0.89 表示模型能解释89%的变化 |

## 6. 错误处理

### 6.1 错误响应格式

```json
  "data": {

  },

```

### 6.2 常见错误类型

| 错误类型 | 可能原因 | 建议处理 |
|----------|---------|---------|
| 数据点不足 | 历史数据太少 | 提示用户需要更多数据 |
| 数据格式错误 | 时间戳或数值格式不对 | 检查数据格式 |
| 服务超时 | 数据量太大或服务繁忙 | 稍后重试 |
| 模型训练失败 | 数据质量问题 | 检查数据是否有异常值 |

### 6.3 前端错误处理建议

## 8. 常见问题

### Q1: 为什么字段名是中文的？

从 v4.0 版本开始，为了提高可读性，所有 API 返回的字段名已改为中文。这样前端开发人员和业务人员可以更直观地理解数据含义。

### Q2: 如何判断分析是否成功？

检查 `是否成功` 字段：
- `true` 或不存在该字段：分析成功
- `false`：分析失败，查看 `消息` 字段获取错误原因

### Q3: 置信区间怎么理解？

置信区间表示预测值的可能范围。例如：
- 预测值：100
- 置信下限：95
- 置信上限：105

表示实际值大概率在 95-105 之间。

### Q4: 趋势方向的值是什么意思？

| 值 | 含义 |
|----|------|
| `"increasing"` | 上升趋势 📈 |
| `"decreasing"` | 下降趋势 📉 |
| `"no trend"` | 无明显趋势 ➡️ |

### Q5: 如何选择趋势分析类型？

- **趋势分解**（decomposition）：想了解数据的组成部分（趋势、季节性、随机波动）
- **趋势检测**（detection）：只想知道数据是涨是跌

### Q6: 单变量预测和多变量预测有什么区别？

- **单变量预测**：只根据一个指标的历史数据预测（如：根据历史销售额预测未来销售额）
- **多变量预测**：综合多个因素预测（如：根据天气、节假日、促销活动预测销售额）
